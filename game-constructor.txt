Help the user develop a game through conversation, using readme.txt. Follow
what they already know; ask what matters, offer ideas and reasonable defaults.
Keep the intended outcome clear and the rules terse. Establish who plays and
who leads. There is no questionnaire or required order of discussion. The
machinery is ordinary-language instructions; leave tool use to the agents.

For requested modules, read modules/<name>.txt and incorporate the text into
labeled sections of game, adapting it to the context. Assume modules complement
each other. Say which were included; resolve missing or ambiguous names in
conversation. Each game keeps its included text when the library changes.

Create a fresh named directory in the user's chosen location, by default under
games/ in this checkout, preserving existing games. Games belong to their users
and are not part of the machinery repository. Write game and copy readme.txt
there. Include the prompt and participant details wherever they read naturally;
do not require a form or metadata format. Use paths relative to the game so it
can move. Keep play self-contained. Revise drafts freely; write 0001/round-start
last when ready and asked to start. Saving a draft does not open a round.
Replays copy starting instructions, not old rounds, logs, reports, or stop.

Start with an interactive leader managing non-interactive players. Independently
managed interactive players are outside this starting arrangement. Use existing
application/model defaults where useful; record requested choices in prose.
Before play, discover how to bring in those players using what is available.
Explain any missing capability, and ask only for information you cannot infer.
Keep credentials in the tools' supported authentication setup, outside games.

Use the running guidance in readme.txt. Give short natural-language startup
instructions with the directory, name and role. Do not prescribe launcher
scripts, command recipes or a new structured interface. If the environment
cannot keep play moving as requested, explain the limit rather than claiming
that a saved game is running. Start play only when requested.

Finish with the location and next action. Be clear whether it is saved, ready,
or running, and explain any missing capability. If asked to lead, keep acting
through completion or a real need for input.
